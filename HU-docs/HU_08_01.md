# HU-008.01 - Archivos e imágenes en el chat

## Historia de usuario

Como estudiante, quiero adjuntar documentos, código e imágenes a mis preguntas para recibir orientación del tutor sobre el material que estoy estudiando.

Rama: `HU-008-fase-8.01-dev`.

## Alcance

- Adjuntos múltiples desde el botón de archivos del cuadro de chat.
- PDF con texto y Word `.docx`, incluyendo párrafos y tablas.
- Archivos de código y texto UTF-8: Python, JavaScript, TypeScript, Java, C/C++, C#, Go, Rust, HTML, CSS, SQL y otros formatos definidos en `Services/attachments.py`.
- Imágenes PNG, JPEG, WebP y GIF estático, enviadas como contenido visual al clasificador y al tutor.
- Posibilidad de enviar únicamente archivos; se utiliza una pregunta inicial predeterminada.
- Mensajes multimodales persistidos en la memoria existente y recuperables al seleccionar el chat. El texto de los documentos se presenta en un desplegable; las imágenes se muestran en el historial.
- Acciones «Limpiar chat» y «Eliminar chat actual» agrupadas debajo de las conversaciones. Limpiar borra mensajes, mientras que eliminar también elimina el chat. No se incorpora papelera ni restauración.

## Límites y validación

- Máximo 4 archivos por mensaje y 5 MB por archivo.
- Hasta 40.000 caracteres de contenido textual combinado, incluidos los encabezados de adjuntos.
- PDF de hasta 50 páginas; no se admiten PDF cifrados.
- Imágenes de hasta 16 megapíxeles; no se admiten animaciones.
- Word descomprimido de hasta 25 MB.
- Archivos dañados, binarios disfrazados de código, formatos no compatibles y documentos sin texto generan un error antes de crear el chat o llamar al modelo.
- El código adjunto se lee, nunca se ejecuta.
- Las instrucciones dentro de documentos e imágenes se tratan como contenido para analizar, no como instrucciones del sistema.

Los adjuntos se envían al proveedor del modelo al enviar el mensaje. La extracción de texto es local. El texto extraído y las imágenes se guardan en el historial SQLite del chat, sujeto al límite existente de mensajes. No hay almacenamiento independiente de los documentos originales ni descargas de adjuntos. Las imágenes aumentan el tamaño del historial y el coste del contexto enviado al modelo.

## Fuera de alcance

- Word antiguo `.doc`: debe convertirse a `.docx`.
- OCR automático para PDF escaneado: se pueden adjuntar las páginas como imágenes.
- Extracción de imágenes incrustadas en PDF o Word y conservación del diseño del documento.
- Ejecución de código, archivos comprimidos, audio y vídeo.

## Componentes

| Archivo | Cambio |
| --- | --- |
| `Services/attachments.py` | Validación, extracción y creación del contenido multimodal. |
| `app.py` | Entrada con adjuntos, visualización del historial y agrupación de acciones. |
| `Graphs/learning_graph.py` | Mensajes multimodales en clasificación, respuesta y memoria. |
| `UI/asistente.py` | Aceptación de consultas de texto o bloques multimodales. |
| `Services/conversation_memory.py` | Recuperación de contenido estructurado sin convertirlo a texto. |
| `Prompts/` | Tratamiento de adjuntos como datos de consulta. |
| `Requirements/requirements.txt` | Streamlit compatible, pypdf, python-docx y Pillow. |

## Criterios de aceptación

1. Enviar texto sin adjuntos conserva el comportamiento anterior.
2. Enviar documentos o código permite al tutor recibir el texto extraído.
3. Enviar imágenes entrega bloques visuales al clasificador y al tutor.
4. Una consulta sin texto pero con adjuntos puede crear una conversación.
5. Volver a una conversación conserva los adjuntos dentro de su historial reciente.
6. Archivos inválidos muestran errores claros sin enviarlos al modelo.
7. Limpiar y eliminar aparecen consecutivamente fuera de la lista de chats.

## Pruebas

Ejecutar desde la raíz:

```bash
venv/bin/python -m unittest discover -s tests -v
```

Se comprueban extracción de PDF y Word, código, archivos inválidos, límites, entrega de imágenes a ambas cadenas, persistencia multimodal, separación de sesiones y acciones de chat mediante AppTest. Las pruebas usan bases temporales y un modelo simulado; no validan la calidad del análisis visual del proveedor real.
