# HU-008 - Rediseño visual e identidad del asistente educativo

## 1. Resumen de la versión

La fase 8 renueva el inicio de sesión y el espacio principal de aprendizaje de Streamlit. Incorpora un icono de robot tutor, una bienvenida personalizada y tarjetas de temas que permiten iniciar consultas. Conserva la paleta celeste, menta y azul del proyecto y los servicios de usuarios, chats y memoria de las fases anteriores.

Rama de desarrollo: `HU-008-fase-8`.

## 2. Historia de usuario

Como estudiante, quiero acceder a una interfaz clara, coherente y adaptable a mi dispositivo, con temas sugeridos y un tutor reconocible, para comenzar una conversación de programación fácilmente y organizar mi aprendizaje.

## 3. Referencias y decisiones de diseño

- Del formulario de referencia se adoptan la composición centrada, los campos redondeados, el botón de acceso ancho, las sombras suaves y el fondo con curvas.
- De la referencia del panel se adoptan la bienvenida personalizada, la ilustración del tutor, las tarjetas de temas, la barra lateral de conversaciones y el estado vacío del chat.
- Se preserva la identidad cromática existente en lugar de incorporar el naranja de las referencias.
- Las imágenes sirven como referencias visuales; los controles implementados corresponden a funciones disponibles en la aplicación.

## 4. Alcance implementado

### 4.1 Acceso y registro

- Presentación de marca con icono y mensaje de bienvenida.
- Formulario centrado y opciones de iniciar sesión o crear usuario.
- Campos redondeados, etiquetas visibles y botón principal de ancho completo.
- Conservación de la validación de credenciales y del registro local existente.

### 4.2 Página principal

- Saludo con el nombre del usuario y perfil de estudiante.
- Robot tutor junto a la bienvenida.
- Tarjetas de Python, videojuegos, robótica y dudas rápidas.
- Estado vacío que invita a escribir una pregunta o seleccionar un tema.
- Entrada de chat disponible aunque aún no se haya creado una conversación.
- Creación automática de un chat al enviar la primera consulta si no existe uno activo.
- Uso del chat activo cuando ya se ha seleccionado una conversación.

### 4.3 Barra lateral e identidad compartida

- Marca, botón de nuevo chat, listado de conversaciones y guía de uso.
- Identificación del usuario y cierre de sesión.
- Conservación de las acciones existentes de selección, limpieza y eliminación de chats.
- Icono compartido en acceso, inicio, barra lateral, favicon y avatar del asistente.
- Estilos adaptables a móvil, con tarjetas apiladas y ajustes de espacio y tamaño.

## 5. Flujo de uso

1. El estudiante inicia sesión o se registra.
2. La aplicación muestra su bienvenida y los temas disponibles.
3. El estudiante escribe una pregunta o pulsa una tarjeta.
4. La tarjeta prepara una consulta inicial relacionada con el tema elegido.
5. Si no hay chat activo, se crea uno asociado al usuario.
6. Se construye el identificador de sesión y se envía la consulta al flujo existente del asistente.
7. Se muestra la respuesta y se actualiza la conversación.

## 7. Criterios de aceptación

| Criterio | Resultado esperado |
| --- | --- |
| Se abre la aplicación sin usuario activo. | Aparece el acceso con formulario centrado e icono. |
| Se introducen credenciales incorrectas. | Se muestra el error y no se inicia sesión. |
| Se completa un registro válido. | Se accede a la pantalla principal con el usuario creado. |
| El usuario accede al panel. | Se muestran su nombre, el tutor y las cuatro tarjetas de temas. |
| Se elige un tema sin chat activo. | Se crea un chat y se procesa la consulta inicial. |
| Se escribe una pregunta sin chat activo. | Se crea un chat antes de enviar la pregunta al asistente. |
| Existe un chat activo. | Las nuevas consultas utilizan esa conversación. |
| Se pulsa nuevo chat. | Se muestra una conversación vacía. |
| Se cierra sesión. | Se regresa al acceso sin eliminar conversaciones guardadas. |
| Se utiliza una pantalla móvil. | Los componentes se reorganizan y el contenido no queda tapado por la cabecera. |
| Se revisan ambas pantallas. | Comparten paleta, icono, bordes redondeados y lenguaje visual. |

## 8. Validación realizada

- Compilación de los módulos Python y revisión de espacios con `git diff --check`.
- Prueba con Streamlit AppTest y una base SQLite temporal: acceso inválido, registro, pantalla principal, selección de Python, creación de chat, nuevo chat y cierre de sesión.
- Revisión visual del formulario y de la página principal en navegador.
- Revisión de la página principal en un viewport móvil de 390 × 844 píxeles y ajuste del espacio superior.

Las pruebas funcionales utilizaron una respuesta de IA simulada. No verifican la disponibilidad del proveedor del modelo ni la calidad de sus respuestas. Los scripts de prueba y la vista previa utilizados fueron temporales; no se incorporó una suite de pruebas permanente en esta fase. La base de datos del usuario no se utilizó para crear los datos de prueba.

## 9. Fuera de alcance

- Recuperación de contraseña y opción persistente de recordar sesión.
- Notificaciones y carga de archivos mostradas en la referencia del panel.
- Cambios en el almacenamiento de contraseñas o en el modelo de autenticación.
- Cambios en LangGraph, en el proveedor del modelo o en el límite de memoria conversacional.
- Despliegue público de la aplicación.

## 10. Relación con fases anteriores

La HU-008 utiliza el registro local y los múltiples chats de [HU-007](HU_07.md), junto con la memoria persistente de [HU-006](HU_06.md). Actualiza la presentación del perfil a nombre y etiqueta de estudiante. El nombre de usuario sigue identificando internamente al propietario de las conversaciones.
